# USDM 要求仕様

# 【MachinakaRestaurantSupportTools】コンポーネント

## 要求

飲食店業務支援ツール群の初期MVPシステムを構築し、8つのサブシステムが連携して店舗業務を一貫して処理できること。

### 理由

各業務ツールが共通の仕様・技術基盤で独立開発されつつ、注文・会計・売上まで途切れなく連携できるようにするため。

### 説明

全体システム設計 `docs/system-design.md` および各サブシステムの USDM 仕様と整合させる。

## 1.要件

### ＜R01＞共通技術基盤とサブシステム構成の確立

#### 要求

全8サブシステムは共通のPython技術スタック（FastAPI / Pydantic / pytest / ruff）を採用し、独立したHTTPサービスおよびテスト可能なアプリケーションとして動作すること。

##### 理由

全リポジトリで開発・テスト・結合試験の手法を統一し、保守性と開発効率を確保するため。

##### 説明

各リポジトリは `pyproject.toml` を持ち、`pytest` と `ruff check` が単独で実行できる構成とする。

#### 下位要求

##### ＜R01-01＞共通API規約とヘルスチェック

###### 要求

各サブシステムはFastAPIアプリケーションを公開し、`GET /health` で稼働状態をJSON返却すること。

- ■■■ **S01-01-01**: 全8サブシステムが `GET /health` に対して HTTP 200 と `{"status": "ok", "service": "<service-name>"}` を返すこと。
- ■■■ **S01-01-02**: リクエスト・レスポンスのシリアライズには Pydantic v2 モデルを使用し、不正入力に対して HTTP 422 を返すこと。

### ＜R02＞マスタ・顧客・注文のコア業務機能

#### 要求

商品管理・メニュー管理・顧客管理・店内注文・持ち帰り注文・注文管理・会計管理・売上管理の各サブシステムが、それぞれの中核業務をAPIとして提供すること。

##### 理由

飲食店の主要業務（商品登録〜メニュー公開〜来店/持ち帰り注文〜調理かんばん〜会計〜売上集計）をデジタル化するため。

##### 説明

初期MVPではインメモリリポジトリをデフォルトとしつつ、API経由で全CRUDおよび状態遷移を実行可能とする。

#### 下位要求

##### ＜R02-01＞商品・メニュー・顧客マスタ管理

###### 要求

商品登録（アレルギー・カロリー・提供時間・持ち帰り可否含む）、メニュー公開設定、座席状態および来客セッション管理を提供すること。

- ■■■ **S02-01-01**: 商品管理は商品の登録・取得・一覧・更新APIを提供し、価格・アレルギー・カロリー・持ち帰り可否を管理できること。
- ■■■ **S02-01-02**: メニュー管理は商品マスタを参照して店内・持ち帰りメニューを作成・公開できること。
- ■■■ **S02-01-03**: 顧客管理は座席ステータス（空席・着席中・清掃中）と来客受付・再利用可否を管理できること。

##### ＜R02-02＞注文・会計・売上業務

###### 要求

店内注文・持ち帰り注文の受付、注文かんばんによる状態管理、会計処理、日次・月次・年次売上集計を提供すること。

- ■■■ **S02-02-01**: 店内注文は席QRトークンに紐づく注文を受け付け、注文管理へ送信できること。
- ■■■ **S02-02-02**: 持ち帰り注文はSNS認証プロバイダ（Google/Facebook/LINE）対応の顧客受付・受取予約・受取通知を提供できること。
- ■■■ **S02-02-03**: 注文管理は店内・持ち帰りの統合注文をかんばん状態（受付→調理中→提供可能→完了）で管理し、会計金額を算出できること。
- ■■■ **S02-02-04**: 会計管理は席・持ち帰り注文の決済を完了し、顧客管理の席状態を更新できること。
- ■■■ **S02-02-05**: 売上管理は完了した会計・注文データから日次・月次・年次の売上集計レポートを取得できること。

### ＜R03＞サブシステム間連携（I-1〜I-6）

#### 要求

全体設計で定義された6つの連携ポイント（I-1〜I-6）がHTTP/JSONインターフェースまたは連携クライアント経由で疎結合に結合できること。

##### 理由

各サブシステムの独立デプロイ性を保ちつつ、結合試験およびE2Eシナリオで整合性を検証するため。

##### 説明

各連携クライアントは httpx（または ASGI テスト用トランスポート注入）をサポートし、単体テスト・結合テスト双方で検証可能とする。

#### 下位要求

##### ＜R03-01＞注文・会計・売上・マスタ連携インターフェース

###### 要求

I-1〜I-6 の各連携ポイントのデータ契約を満たし、E2Eの業務フローが正常に完了すること。

- ■■■ **S03-01-01**: I-1（店内注文→注文管理）および I-2（持ち帰り注文→注文管理）の注文登録連携が成功すること。
- ■■■ **S03-01-02**: I-3（注文管理→会計管理）の決済連携と I-6（顧客管理↔会計/注文）の席状態・会員更新連携が成功すること。
- ■■■ **S03-01-03**: I-4（注文管理/会計→売上管理）の売上データ供給連携と I-5（商品/メニュー管理→注文ツール）のメニュー参照連携が成功すること。
