# USDM 要求仕様

# 【MachinakaRestaurantSupportTools】コンポーネント

## 要求

サブシステム間のAPI契約を堅牢化し、ID型の統一・同一席での複数注文および分割会計・注文時の正本価格参照を一貫して実現すること。

### 理由

結合試験（Issue #3）で判明したID型不整合・同一席複数決済時の409エラー・クライアント指定単価の信頼問題を解消し、実店舗運用でのデータ整合性と安全性を担保するため。

### 説明

全体システム設計 `docs/system-design.md` および対象4サブシステム（`product_management`, `accounting_management`, `dine_in_ordering`, `takeout_ordering`）の USDM 仕様を更新する。

## 1.要件

### ＜R04＞サブシステム間契約の堅牢化

#### 要求

商品IDの型統一、同一席における複数注文の分割会計制御、および注文確定時の商品マスタ正本価格参照をシステム全体で保証すること。

##### 理由

サービス間の型変換や運用上の制約（1席1注文制限）、およびクライアント側からの価格改ざんリスクを排除するため。

##### 説明

各サブシステムは既存APIの後方互換性にも配慮しつつ、契約上の不整合を解消する。

#### 下位要求

##### ＜R04-01＞商品ID型の文字列統一

###### 要求

`product-management` が発行する商品IDを他サブシステムと同一の文字列型（`str`）に統一すること。

- □□□ **S04-01-01**: 商品管理の登録・取得・更新・一覧APIが返す商品 `id` およびパスパラメータ `product_id` がすべて文字列型（例: `prod-<hex>`）であること。

##### ＜R04-02＞同一席での複数注文・分割会計時の清掃遷移制御

###### 要求

同一席に複数の未払い注文が存在する状態で一部の注文のみを決済した際、未払い注文が残っている間は座席を清掃中へ遷移させず、全注文が支払済みとなった時点で清掃中へ遷移させること。

- □□□ **S04-02-01**: 会計管理が店内注文の決済を完了した後、注文管理の席請求API（`GET /tables/{table_id}/bill`）で未払い注文が残存している場合は顧客管理の `request-cleaning` を呼び出さないこと。
- □□□ **S04-02-02**: 同一席の最後の未払い注文が決済され未払い注文が0件となった場合のみ、会計管理が顧客管理の `request-cleaning` を呼び出して席を `cleaning` 状態へ遷移させること。

##### ＜R04-03＞注文確定時の商品マスタ正本価格参照

###### 要求

店内注文および持ち帰り注文の確定時、クライアントが送信した単価ではなく商品管理マスタの正本価格を参照して注文金額を確定すること。

- □□□ **S04-03-01**: 店内注文が注文作成時に商品管理（`GET /products/{product_id}`）から正本価格・商品名を取得し、正本価格で注文明細を確定すること（未登録商品は HTTP 404/422、店内発持ち帰りで持ち帰り不可商品は HTTP 422）。
- □□□ **S04-03-02**: 持ち帰り注文が注文作成時に商品管理（`GET /products/{product_id}`）から正本価格・商品名・持ち帰り可否を取得し、正本価格で注文明細を確定すること（未登録商品は HTTP 404/422、持ち帰り不可商品は HTTP 422）。
