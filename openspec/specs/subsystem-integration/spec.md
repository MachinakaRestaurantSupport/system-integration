# subsystem-integration Specification

## Purpose
全体システム設計で定義された連携ポイント I-1〜I-6 を通じて、8つのサブシステムが疎結合にデータ連携し、店舗業務のE2Eシナリオを完結できることを定義する。

## Requirements

### Requirement: 注文生成から注文管理への連携（I-1, I-2, I-5）
**USDM**: R04-03
店内注文および持ち帰り注文サブシステムは、メニュー管理から公開メニューを参照し（I-5）、注文確定時に商品管理から正本価格・商品名・持ち帰り可否を取得して金額を確定した上で注文管理サブシステムへ連携（I-1, I-2）しなければならない（SHALL）。

#### Scenario: 店内QR注文から注文管理への登録
- **WHEN** 店内注文サブシステムが席QRトークンに紐づくメニュー注文を確定する
- **THEN** 商品管理の正本価格で明細金額が算出され、注文管理サブシステムに店内注文が登録され、かんばんステータスが受付済みとなる

#### Scenario: 持ち帰り事前注文から注文管理への登録
- **WHEN** 持ち帰り注文サブシステムがSNS認証済み顧客の受取予約注文を確定する
- **THEN** 商品管理の正本価格と持ち帰り可否が検証された上で注文管理サブシステムに持ち帰り注文が登録され、注文状況確認が可能となる

### Requirement: 会計完了と席状態・売上集計への連携（I-3, I-4, I-6）
**USDM**: R04-02
会計管理サブシステムは注文管理から会計金額を取得して決済を完了し（I-3）、売上管理への売上データ供給（I-4）を行うとともに、店内注文では同一席の未払い注文が0件となった場合のみ顧客管理の清掃要求（I-6）を呼び出さなければならない（SHALL）。

#### Scenario: 店内会計完了後の席解放と売上計上
- **WHEN** 注文管理の注文に対して会計管理で決済を完了する
- **THEN** 未払い注文が0件であれば顧客管理の座席ステータスが清掃中（または再案内可能）へ更新され、売上管理に売上レコードが計上される

#### Scenario: 同一席の分割会計1回目における席状態維持
- **WHEN** 同一席に2件の未払い注文が存在する状態で1件目のみを会計管理で決済する
- **THEN** 1件目の注文が支払済みかつ売上計上され、未払い注文が残っているため顧客管理の座席ステータスは着席中のまま維持される

#### Scenario: 同一席の最終注文決済完了後の席清掃遷移
- **WHEN** 同一席の最後の未払い注文を会計管理で決済する
- **THEN** 対象席の未払い注文が0件となり、顧客管理の座席ステータスが清掃中へ遷移する

### Requirement: 全サブシステム間の商品ID型統一
**USDM**: R04-01
商品管理サブシステムはすべての商品IDを文字列型（`str`）として生成・返却しなければならず（MUST）、全サブシステム間で型変換なしに商品IDを連携できなければならない（SHALL）。

#### Scenario: 商品IDの文字列型での登録と他サブシステム連携
- **WHEN** 商品管理で新規商品を登録し、その返却IDをそのままメニュー管理および注文サブシステムへ渡す
- **THEN** 返却された商品IDは文字列型であり、メニュー公開および注文確定が型変換なしで成功する
