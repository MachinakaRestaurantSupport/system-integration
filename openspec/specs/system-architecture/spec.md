# system-architecture Specification

## Purpose
MachinakaRestaurantSupportTools を構成する8つのサブシステムが共有する技術基盤、HTTP API 規約、および各サブシステムが提供すべき中核業務APIの契約を定義する。

## Requirements

### Requirement: 共通技術スタックとヘルスチェックAPIの提供
**USDM**: R01-01
すべてのサブシステムは Python 3.12 および FastAPI / Pydantic v2 を用いて実装されなければならず（MUST）、`GET /health` エンドポイントで稼働状態とサービス名を返却しなければならない（SHALL）。

#### Scenario: ヘルスチェック成功
- **WHEN** クライアントが任意のサブシステムの `GET /health` にリクエストを送信する
- **THEN** システムは HTTP 200 と `{"status": "ok", "service": "<service-name>"}` を返却する

#### Scenario: 不正なリクエストボディの拒否
- **WHEN** クライアントが必須フィールド欠落または型不正の JSON を送信する
- **THEN** システムは Pydantic バリデーションにより HTTP 422 を返却する

### Requirement: マスタおよび顧客座席のコアAPI提供
**USDM**: R02-01
商品管理・メニュー管理・顧客管理の3サブシステムは、それぞれの責務に応じた登録・参照・状態更新の REST API を提供しなければならない（SHALL）。

#### Scenario: 商品登録とメニュー公開
- **WHEN** 商品管理で商品（価格・アレルギー・カロリー・持ち帰り可否）を登録し、メニュー管理で公開メニューを作成する
- **THEN** 登録した商品が公開メニュー経由で店内および持ち帰り注文用に参照可能となる

#### Scenario: 座席受付と再利用可否管理
- **WHEN** 顧客管理で空席に対して来客受付を実行する
- **THEN** 座席ステータスが着席中に遷移し、来店セッションIDが発行される

### Requirement: 注文・会計・売上のコアAPI提供
**USDM**: R02-02
店内注文・持ち帰り注文・注文管理・会計管理・売上管理の5サブシステムは、注文受付・かんばん進行・決済処理・売上集計の REST API を提供しなければならない（SHALL）。

#### Scenario: かんばん状態遷移と会計金額算出
- **WHEN** 注文管理で新規注文を受け付け、調理中・提供可能へと状態遷移させる
- **THEN** 注文ステータスが更新され、対象席または持ち帰り注文の合計会計金額が算出される

#### Scenario: 日次・月次・年次売上集計
- **WHEN** 売上管理に完了済み売上データを記録し、日次・月次・年次集計APIを呼び出す
- **THEN** 指定期間の件数および合計売上金額が返却される
